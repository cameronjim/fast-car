# Racer app: fixes from the first real car session (2026-11-12)

Extends `racer-app-2026-11-11.md`. Nothing here has run on the Jetson; it is tested against the
fake docker layer (agent), vitest (web) and cargo tests (desktop).

## Updating the Jetson

After a change to the repo, on the Jetson, in `~/car`:

```sh
git stash push -m jetson-hotfix        # only if `git status` shows local hotfixes; pop them after
git pull
docker run --rm --runtime nvidia -v "$PWD":/workspace -w /workspace car:local bash -lc '
  source /opt/ros/humble/setup.bash
  cd ros_ws && colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release'
tools/racer_app/deploy/install.sh
git stash pop                          # if you stashed; look at what conflicts, do not force it
```

- The `colcon build` has to be the Release one (a build with no build type compiles without
  optimisation, which is what made the 2026-10-25 scan callback slow).
- `install.sh` is safe to re-run. It never changes the token or the autostart choice. It builds the
  web UI with no npm on the host (below) and restarts `racer-agent`. The running stack and any
  recording are not touched: restart the stack from the app when you want new ROS code.
- A local hotfix that lives only on the Jetson belongs in a branch on the Mac. Stash it, do not
  `git checkout .` it away.

## What changed

| Bug | Fix |
|---|---|
| Stop stack left a bag with no footer and no `metadata.yaml` | Every stop (Stop stack, Restart, Reboot, Shut down, the disk guard, and `racer-stack.service` on stop) sends SIGINT once and waits up to `stop_timeout_stack_s` (600 s) for the container to exit before SIGTERM (then 20 s, then SIGKILL). Cameras and perception wait `stop_timeout_other_s` (120 s). The action log says what happened: the signal, how long it took, the exit code, and whether the bag has `metadata.yaml`. A stop that needed SIGTERM or SIGKILL, or left no `metadata.yaml`, is logged as failed (red). All three numbers are in `/etc/racer-app/config.json`. |
| PnP log said `"dynamics": ""` | The request must name the dynamics bundle (an empty one is a 400 even with a single bundle), the card shows the selection, and the log line and params carry the bundle, perception bundle, planner file and speed cap. |
| A drive started with `docker exec ... ros2 launch` was invisible | The agent scans `/proc` in `car-stack` for `ros2 launch` or `ros2 run` of gap_follow, wall_follow, track_follow, tracker, park, pnp, policy and spiderbot. They show in the Driving card, block a second start, and STOP ALL (and a stack stop, and the disk guard) SIGINTs them with the same escalation as an app drive. |
| No planner file or max speed from the app | PnP card: a picker over `data/pnp/*.yaml` (plain files, shell-safe names, listed by the agent), passed as `params_file:=`. Gap follow card: a max speed box, bounded by the profile's ceiling and `vehicle_params` `limits.global_speed_cap_mps` (read at run time), passed as `max_speed_mps:=`. Empty means the profile's own speed. |
| Token lost three times | Desktop app: when the keychain refuses a read or write, the token is kept in `<app data>/token` (mode 0600) and the choice is remembered, so the keychain password prompt stops. The UI says which store is in use. A token the car rejects clears the saved one and shows "paste a new one"; a typed token is checked against the car before it is saved. The agent still stores only the hash and there is still no way to show the token. A lost token is replaced with `racer-agent init --rotate-token` on the Jetson. |
| "Search again" did nothing visible | It runs a full search and shows searching, then "Found N cars" or "No car found" with what to check. |
| install.sh web build | `deploy/build-web.sh`: pinned node container (host node only if 22.12 or later), `node_modules` kept and `npm ci` only when `package-lock.json` changed, npm cache in `web/.npm-cache`, one retry, `dist/` replaced by a rename only after a successful build, and a root-owned leftover is named with the `chown` that fixes it. The typecheck is left to CI. |

## Not verified on the Jetson

- The `docker kill -s INT` wait with a real multi-GB bag, and the `ExecStop` of
  `racer-stack.service` at a real shutdown (`TimeoutStopSec=720`).
- The `/proc` scan inside the real image (busybox or procps differences: it uses `tr` and a bash
  `case`), and that a terminal-started `ros2 launch` shows `ros2` as argv[1] there.
- The node container build on aarch64, and the keychain behaviour of a real unsigned rebuild.
